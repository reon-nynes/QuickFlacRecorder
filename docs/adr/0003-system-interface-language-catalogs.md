# Resolve interface language once and embed message catalogs

Accepted for [issue #10](https://github.com/reon-nynes/QuickFlacRecorder/issues/10), 2026-10-11.

The recorder selects an interface language before constructing its window on every launch. Platform adapters return ordered preferences. Windows calls [GetUserPreferredUILanguages with MUI_LANGUAGE_NAME](https://learn.microsoft.com/en-us/windows/win32/api/winnls/nf-winnls-getuserpreferreduilanguages); macOS reads [NSLocale.preferredLanguages](https://developer.apple.com/documentation/foundation/nslocale/preferredlanguages) in Objective-C++; Linux reads [message-locale environment variables](https://www.gnu.org/software/gettext/manual/html_node/Locale-Environment-Variables.html). Linux applies LC_ALL, LC_MESSAGES, then LANG to establish the message locale, respects ordered LANGUAGE entries outside an effective C/POSIX locale, and treats unset or C/POSIX message locales as English. Adapters neither change user settings nor consult numeric/date or keyboard settings.

The deterministic resolver normalizes BCP 47 tags while retaining script and region. Each preference tries exact matches, script matches, then generic language matches. At each level, catalog tags precede normalized aliases. The next supported preference wins when earlier preferences are unsupported. English is the final fallback. Register `en` and `zh-Hans`; the initial generic `zh` alias deliberately selects Simplified Chinese even for Traditional Chinese preferences. Future exact/script registrations precede that generic alias. Detection failures produce an empty list and select English.

`i18n::Translation` owns an immutable selected language and compiled templates. Presentation receives that value by injection. Recorder preferences never persist language. The single shared registry, `src/localization/languages.json`, declares tags, names, aliases, embedded resource references, and plural-rule metadata. Each language has one UTF-8 JSON catalog. `Messages.def` supplies typed stable message IDs, named text/number argument schemas, and translator context. Message identities do not depend on English wording.

Use a module-owned, bounded template parser for complete messages with named substitutions, nested cardinal `plural` and `select` alternatives, mandatory `other` branches, exact integer plural branches, and `#` substitution. This is a documented subset inspired by [ICU message formatting](https://unicode-org.github.io/icu/userguide/format_parse/messages/), not an ICU-compatible implementation. The English rule uses `one` for an absolute number of 1 and `other` otherwise; Chinese uses only `other`, following [CLDR cardinal categories](https://unicode.org/cldr/charts/49/supplemental/language_plural_rules.html). The module currently has these two registered rule families. A language needing additional categories requires a rule within this module and reference cases, without changes to recorder callers or OS adapters. Ordinals, decimal precision operands, plural offsets, date/number skeletons, and ICU apostrophe escaping are outside this formatter's contract.

Numeric substitutions use classic-locale streams and retain enough significant digits to preserve the supplied finite double. The module tries increasing precision until the value round-trips, with `max_digits10` as its safe fallback. Exact integer plural branches compare numeric values independently of their display representation. Floating-point `to_chars` and `from_chars` have newer Apple deployment requirements, so this implementation uses streams to preserve the accepted macOS 12 baseline. See [Apple's C++ library availability](https://developer.apple.com/xcode/cpp/).

This choice avoids a new ICU runtime/data dependency for two catalogs while retaining locale-specific grammar behind a small interface. JUCE supplies JSON-string decoding and Unicode/font shaping. The parser rejects duplicate decoded catalog keys, invalid JSON escapes, missing/unknown messages, empty templates, invalid syntax, argument name/type mismatches, duplicate variants, and missing plural/select defaults. It limits template size to 16 KiB and nesting to 16 levels. Runtime discards unusable translated entries and renders the complete English template with the original values and English plural rule. An invalid canonical English catalog fails construction and validation, since no trustworthy fallback would exist.

CMake embeds catalogs and registry in JUCE BinaryData linked into every executable. No external formatter resources, adjacent translation files, or runtime network request are needed. On macOS, CMake also generates localized InfoPlist.strings microphone usage explanations from the same catalogs and includes them in the app bundle. The existing static Windows runtime, universal macOS bundle, and Linux AppImage packaging contracts remain applicable.

RecordingSession exposes result codes, file values, and state independently of language. Presentation selects and formats normal and failure messages. Catalog access and formatting stay outside RecordingSession and audio callbacks. The recording action has explicit state, and native driver/device identity remains separate from display annotation.

Issue #11 extends this decision to recorder validation, input, permission, startup, and failed-saving outcomes. `RecorderResult` contains a stable `ErrorCode` plus original native data. A session snapshot preserves the interruption reason, finalization outcome, retained file, incomplete flag, and separate native input/disk diagnostics. Complete catalog templates select clauses using those stable values and format count grammar through the same translation module. Passive preview refresh and late stop/device notifications preserve terminal results. Explicit configuration or a new take can reset them. CMake derives macOS supported localizations and microphone usage descriptions from the registry/catalogs; package verification checks declarations as well as localized resources.

Focused tests exercise adapter inputs, ordered resolution, malformed tags, future script/exact priority, named arguments, complete-message fallback, catalog validation, a registered third test language, real session success, and caption-independent controls. Windows has local rendering and input evidence. Linux WSL has compiler, shared-test, embedded-resource, and isolated Chinese font-rendering evidence. macOS and wider native Linux recording, dialogs, permission resources, and packaged runtime verification require their target environments and are explicitly tracked in the validation report.
